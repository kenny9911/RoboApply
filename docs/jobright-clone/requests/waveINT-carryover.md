How to use this file:
- **WP-90 … WP-97 agents:** read your section. Each item names the asking bundle in brackets, the files, and the acceptance it implies.
- **Fix WPs:** the section "WP-93 follow-ups" is grouped by the bundle whose files the change is in (INT-01 … INT-13). A fix WP owns only the files its item names. Items marked **launch** should be done before the brand they concern goes live; the rest are improvements.
- **Owner:** the "Owner" section lists decisions, credentials and counsel items the code waits on, and the choices bundles made that the owner may want to overrule.

Rules added at the INT gate that apply to every later change:
- **SCHEMA-6 must be pushed before this tree runs against a database.** `RAAutofillRun.pageUrl` is selected by every extension run read (`features/extension/repository.ts`), so `/ext` run routes fail with P2022 without it; `POST /credits/cancel/survey` answers `503 storage_unavailable` until `RACancelSurvey` exists. Diff: `docs/jobright-clone/schema-diffs/schema6-additive.sql` (1 nullable column, 1 table, 3 indexes, 1 foreign key; no DROP / ALTER COLUMN / RENAME). The gate's own schema edits are doc comments only (`prisma migrate diff` against the pre-gate schema is empty).
- **Earlier pushes are still a precondition** [INT-05]: the target database needs `RAJob.originalHost` (SCHEMA-2), `RAFeedSession.windowEndsId` (SCHEMA-3) and `RAJobReview` (SCHEMA-5), or the first feed page, every job report and every ingest batch fail. There is no fallback.
- **GoApply WeChat Pay needs a published 用户协议 (join J5).** The order gate asks compliance for `publishedLegalDocVersion(brand, 'terms')`. `content/legal/cn/user-agreement.md` is `status: draft`, so every order answers `409 terms_outdated` (`details.currentVersion: null`) until counsel's text is published and `CN_LEGAL_DOCS_VERSION` is set. Tests read a published fixture through `LEGAL_CONTENT_DIR` (`server/src/features/billing-cn/__tests__/fixtures/legal`).
- **Job alerts select through the feed (join J4).** `defaultJobAlertsDeps` calls `feedService.alertCandidates(searchProfileId, { since, limit, postedSince })` inside the recruitment-info gate. `AlertsRepo.candidateJobIds` remains for tests only.
- **The re-engagement "N new jobs" count reads the same seam (cross-WP review after the gate).** `lifecycle/service.ts` `countNewJobsWith(modeGatedCandidates(feedService.alertCandidates))`: the number in `notify.tipsReEngagement` follows the feed's rules (radius, posted-within, GoApply fields, no seed rows, the posted-date floor, hidden jobs). More than 400 new jobs (`FEED_LIMITS.retrievalLimit`) means no exact N, and the message is not sent. `AlertsRepo.countMatchingJobs` is deleted.
- **A `tailor_ready` card opens its own session.** The Assistant's href is `/resume/<base>?tailor=<jobId>&tailorSession=<sessionId>` (`copilot/proposals.ts` `tailorSessionHref`). Any other producer of a link to a session that already exists must carry `tailorSession`, or the web starts a new run and a second credit.
- **Legacy routes that return postings or call a model are gated.** `POST /v2/discover/run`: session → `RA_V2_DISCOVER_DISABLED` → GoApply recruitment-info mode → `legacyAiGates()`. The job-search API (`/api/v1/job-search/*`, `/api/v1/roboapply/v2/job-search/*`) and its two pages are 404 on GoApply in every mode. A job-search key owned by a GoApply account is invalid on every host (`keys.ts` `authenticate`). `RA_CROSSBANK_DISABLED` is not a route switch: it also turns off the bank ingest adapters.
- **The Assistant reads no other area's table (joins J1, J2).** `copilot/areas.ts` uses feed `marketStats.salary`, feed `feedSignals` and resume `primaryVariantId`. `copilot/salaryStats.ts`, `createPrismaNudgeSignals` and `store.primaryResumeId` are deleted; a guard test fails if a direct read comes back.
- **Admin limits are re-exports (join J3).** `features/admin/limits.ts` re-exports `scoreDailyBudget`, `scoreCounterKeys` (match), `copilotDailyBudgetUsd` (copilot) and `dailyCallLimit` (jobs/ingest). Only `enrichCounterKey` is still a mirror.
- **A kept job stays open.** `KEEP_DECISION_HOLDS = true` in `features/admin/reports.ts`; a guard test compares it with the feed's source.
- **`typecheck:web` reads `.next/types`.** A stale production build there (the gate found one naming the deleted `/job-search` page) fails the type check. Run `npx next typegen` first; it does not touch a running `next dev`.
- **`@vitest/coverage-v8` is installed** in the clone worktree (`npm install`, lockfile unchanged).
