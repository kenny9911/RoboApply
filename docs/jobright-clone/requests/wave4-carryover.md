# Wave 4 carry-over requests

**Written at the Wave 4 gate (SCHEMA-4 + G5), 2026-10-10.** Source: the 16 Wave 4 handoffs (WP-50 … WP-59, WP-61, WP-62, WP-63a, WP-65, WP-66). Everything below was asked of a later work package, of INT, or of the owner, and was **not** done at the gate. What the gate applied is listed at the end for context. `wave2-carryover.md` and `wave3-carryover.md` still apply; items here do not repeat them unless a Wave 4 handoff re-raised them.

How to use this file:
- **Feature agents (Wave 5):** read your own section. Each item names the asking WP (in brackets), the seam to use and the acceptance it implies. Your owned paths still rule: if an item needs a file you do not own, put it in your handoff's Requests.
- **INT (WP-90 … WP-97):** the INT sections are your backlog from Wave 4. Requests that Wave 4 WPs addressed to packages that have no owner any more are routed to WP-93.
- **Owner:** the "Owner" section lists decisions, credentials and data the code waits on.

Rules added in Wave 4 that apply to every later WP:
- **Schema columns that exist after the SCHEMA-4 push** (not before). The generated client selects new columns on every default read, so against a database without SCHEMA-4 these reads fail with P2022: **`InterviewSession`** (`brand`, `voiceProvider`: every practice session read), `AlipayOrder` (`termsVersion`), `RAAgentSettings` (`searchProfileId`, `filterOverrides`), `RAAgentKitEvent` (`kind`), `RAContact` (`companyName`), `RAAnnouncement` (`active`, `updatedAt`), `RAInterviewQuestion` (`jobId`), `RAQuestionContribution` (`category`, `rejectReason`); new models `RACnReferralCode`, `RACnReferralReport`. Do not add `'col' in Prisma.*ScalarFieldEnum` shims.
- **Ready to apply ↔ extension:** "is an extension connected" is `hasConnectedDevice(userId, brand)` from `server/src/features/extension/index.ts` (gate). The only submit signal is `agentService.markUserSubmitted` (WP-52); the extension never detects submits (D1).
- **Free-tool purge** runs hourly in the `reminders` cron as well as daily in `jobs-maintain` (gate).
- **Rate limits** `seoPublicPerIp` and `billingCnCreate` now live in `RATE_LIMITS` (`platform/ratelimit/defaults.ts`) and are tunable through `RATE_LIMITS_JSON`. Add new public limits there, not as area constants.
- **Error code** `gone: 410` exists in `platform/http.ts`; use `httpError('gone', …)` for closed/removed public resources.
- **Consent type** `cn_pay_terms_ack` is in `SEEKER_CONSENT_TYPES`.
