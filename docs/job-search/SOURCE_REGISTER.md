# Source register: where job postings come from, and what we may do with them

**Written:** 2026-10-12 (market wave, bundle MKT-5D; requirement JI-12 of `docs/jobright-clone/market/MARKET_STRATEGY.md`).
**Not legal advice.** The register records what the research notes and the sources' own pages say. The open points are listed per row and belong to the owner or to counsel.

One row per provider id that the code knows (`PROVIDER_META` in `server/src/features/jobs/normalize/source.ts`). A test reads this file (`server/src/features/jobs/sources/sourceRegister.test.ts`): it fails when a provider id has no row, when a row has no date read, when a required cell is empty, and when a forbidden site of section 2 appears among the providers. **Add the row in the same change that adds a provider.**

## How to read it

- **Where a fact comes from.** Every figure and every statement about a licence is followed by its place in a research note: `INTL` = `docs/jobright-clone/market/JOB_SOURCES_INTL.md`, `TW` = `JOB_SOURCES_TW.md`, `CN` = `JOB_SOURCES_CN.md` (all researched 2026-10-11), `STRATEGY` = `MARKET_STRATEGY.md`. The notes hold the primary links and their own confidence marks (confirmed, likely, inferred); a mark is repeated here when it is not "confirmed". Three rows also cite a page read on 2026-10-12 for this register (`activejobs`, `tw_gov_jobs`, `usajobs`); those say so.
- **"not stated"** means the source's terms say nothing on the point, as far as the note or the page read shows. **"unresolved"** means the question is open and somebody has to answer it. Neither is ever filled with a guess (D3).
- **Surfaces.** *Signed-in* = shown to our own signed-in users (feed, search, job page, alerts). *Public* = a page anyone can open and a search engine can index. *Partner API* = our job-search API for integrators.
- **Date read** is the day the terms or the dataset record were last read. A plan, a price or a quota is a snapshot of that day. Re-read a row before relying on it for a new surface.
- **Status** is what the code does with nothing set, as of phase M5 of the market wave. It is one of: `on` (read by default), `off until …` (built, waits for a key, a plan, a flag or a decision), `not a source`. `on` is not a statement about rights: where the permission is unresolved, the surfaces cell and the last column say so, and section 3 names the switch.

Notes on the table:

- An `ats_public` row describes a board system. The single boards (512 seeded on 2026-10-11) are listed and validated in `docs/jobright-clone/market/BOARD_SEEDS.md`; a board is read only after it answered on its public API under the name its entry carries.
- A posting with no usable apply link is never listed, whatever its source (STRATEGY 1.4).
- Sponsorship, pay and applicant counts follow their own rules (STRATEGY 1.5): no applicant count is ever taken from `jsearch`, `linkedin` or a government source.
- The register covers sources of job postings. The sponsorship publications behind the facts on a company's page (the U.S. Department of Labor's LCA disclosure data, the USCIS H-1B Employer Data Hub, the UK register of licensed sponsors; requirement JI-11) are not job sources and have no row here: each fact shown names its publication, file and date.

## 4. Public display (`PUBLIC_DISPLAY_PROVIDERS`)

`PUBLIC_DISPLAY_PROVIDERS` is a comma list of provider ids whose rows may be marked for public display. **Its default is empty and stays empty until the owner decides** (STRATEGY 7 item 15; OPS-A4).

| Provider | Candidate? | Why |
|---|---|---|
| `tw_open_data` | **Yes, recommended first entry** (STRATEGY 7 item 15). | OGDL v1 permits public redisplay with the attribution sentence (TW 3.1). |
| `usajobs` | **Yes, recommended first entry** (STRATEGY 7 item 15). | An official API whose terms call the data public data under an open licence (section 1). |
| `tw_gov_jobs` | Yes, under the same licence as `tw_open_data`. The strategy does not name it among the first entries, so it waits for the same decision. | OGDL v1 (TW 3.2). |
| `ats_public` | Not yet. | Counsel on public display of employer-board rows (INTL 4.4; STRATEGY 7 item 15). |
| `activejobs`, `activejobs_feed` | Not yet. | The vendor's written answer on public pages (INTL 10). The two ids write the same rows under one licence: naming `activejobs` covers the feed's rows as well; naming `activejobs_feed` alone marks the feed's rows, which no public job page then lists (point 2 below). |
| `jsearch`, `linkedin` | Never. | STRATEGY M-3 and M-4; the code ignores them in the list. |
| `bank_robohire`, `bank_gohire` | Not through this list. | A bank row is public only when its employer consented to syndication. |
| `user_import` | Never. | Private to the user. |

What the list does today, so that nobody expects more from it:

1. The normalizer marks a row `publicDisplay` when its provider is in the list at the moment the row is ingested. A change of the list reaches a row the next time the source lists it. `tw_open_data` and `tw_gov_jobs` rows are read again every day; a `usajobs` row is read once, when it is posted.
2. The public job pages, the ticker and the sitemap take their boards from `PROVIDER_BOARDS` in `server/src/features/seo/scope.ts`, which today knows `activejobs` and `ats_public` only. Naming `tw_open_data`, `tw_gov_jobs` or `usajobs` in the list therefore puts no job page of theirs online yet: each needs its line there, and the two Taiwan datasets may be shown only where their credit line is printed (the visitor list does not print it yet; `docs/jobright-clone/requests/waveM3-carryover.md`, Owner 6). One surface does follow the mark alone: a company's job list and its open-job count (`GET /companies/:id/jobs`, `companies/service.ts` `liveJobWhere`) answer a signed-out caller with every row marked for public display, whatever its board, and each row that owes a credit line is sent with it (`cardMeta.tw_sources.attribution`; the Company tab prints it). So naming one of the three ids does publish those rows there.
